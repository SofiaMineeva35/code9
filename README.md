# КОД9 — краткий и интерактивный бриф

Перенос готового компонента из Figma в React и обычный CSS. Сборка — Webpack. Макеты Figma не изменялись.

[Исходные макеты](https://www.figma.com/design/o9CH5WfSTNJoasu6kJoOT6/КОД9?node-id=166-5699) · [Репозиторий](https://github.com/SofiaMineeva35/code9)

Публичный адрес и состояние публикации указаны в [документе сдачи](docs-project/DELIVERY.md).

## Запуск

Нужен Node.js 22 LTS (минимум 20.19).

```bash
cd /Users/sofamineeva/Desktop/Code9
npm ci
npm start
```

Откройте адрес, который покажет терминал, обычно http://localhost:8080. Остановка — Ctrl+C.

```bash
npm test
npm run build
```

Готовый сайт появляется в `docs/`. Эта папка создаётся заново из исходников; её не нужно коммитить. Для проверки сборки:

```bash
python3 -m http.server 4173 --directory docs
```

Откройте http://localhost:4173. В другом окне терминала можно запустить браузерные проверки:

```bash
npx playwright install chromium
npm run test:browser
node tests/edge-cases.cjs
```

Тесты используют вымышленные данные. Скриншоты, отчёты и PDF попадают в `test-results/` и исключены из Git. `BASE_URL` позволяет проверить другой адрес. Для открытия HTML нужен веб-сервер: двойной клик по файлу не подходит для загрузки шрифта PDF.

## Что работает

- Краткий бриф: описание, почта/телефон/Telegram, имя, компания, файлы, ссылка, согласие.
- Интерактивный: два вопроса с вариантами и собственным текстом, затем проверка и контакт; «Пока не знаю» позволяет продолжить без подробностей.
- Возврат и изменение отдельных ответов, переключение двух брифов, общий контакт и вложения.
- Проверка полей, формата/размера/количества файлов, ссылки; удаление, отмена чтения и повтор при ошибке чтения.
- Учебное завершение, просмотр результата, PDF с русским текстом и переносом на новые страницы.
- Клавиатура: Tab, Shift+Tab, стрелки в группе ответов, Space для выбора и согласия, Enter для кнопки. Новый шаг получает фокус на заголовке.
- Видимый контекст входа `?project=PowerDot` можно убрать. Он не появляется сам без параметра ссылки.

## Пример: ответ → данные → интерфейс

Пользователь выбирает «Есть идея нового продукта».

1. Радиокнопка вызывает `update('existing', option)` в `BriefApp.jsx`.
2. Создаётся новый объект `draft`; `draft.existing` получает выбранный текст. React сохраняет его через `setDraft`.
3. `useEffect` записывает текстовый черновик в `sessionStorage` под ключом `code9.brief.v1`.
4. React обновляет экран: у ответа появляется чёрный фон и выбранный значок, кнопка «Дальше» становится доступной.
5. На третьем шаге `answer(draft, 'existing')` выводит этот ответ. Возврат назад меняет только `draft.step`, ответ сохраняется.

При переходе в краткий бриф `combinedText` собирает ответы в описание. Если краткий текст уже редактировался вручную, `shortEdited` защищает его от перезаписи. Правки краткого текста не меняют ответы интерактивных шагов.

## Как хранятся данные

`draft` — текстовые ответы в памяти React и в `sessionStorage` текущей вкладки. Согласие изначально выключено. Каждый канал сохраняется в черновике отдельно, в итог попадает только выбранный контакт. В обычном режиме закрытие вкладки завершает её сессию; поведение восстановления закрытых вкладок зависит от браузера. При запрете хранилища приложение продолжает работать в памяти и показывает предупреждение.

`files` — локальные объекты File в памяти. Их читаем через FileReader, чтобы обнаружить ошибку чтения. Они никуда не загружаются. Сохраняются только имена для предупреждения после перезагрузки; файлы нужно прикрепить заново. Допускаются PDF, DOCX, TXT, PNG, JPG/JPEG, до 20 МБ каждый, максимум 5, включая строки с ошибками.

При завершении `makeSnapshot` создаёт отдельную копию итоговых текстов, выбранного контакта, имён файлов, ссылки и времени обработки. PDF генерируется именно из неё, поэтому поздние изменения черновика не меняют готовую копию. В PDF нет содержимого вложений и внутренних идентификаторов.

## Отправка и ограничения

Готового API, сервера и почтового сервиса в исходном проекте нет. Это учебная обработка в браузере. Нажатие «Отправить запрос» **не доставляет заявку**. Экран результата и PDF говорят об этом явно. Платные сервисы не подключены, ключей нет.

Черновик не очищается после учебного завершения: подтверждения от сервера нет. «Вернуться к брифу» позволяет продолжить с теми же данными. В отличие от серверного макета результат называется «Бриф подготовлен», без обещания ответа от команды.

Реальные HTTP-состояния макета (нет соединения, неизвестен статус запроса, 429 и ошибка сервиса), серверная защита от дублей и фоновая обработка требуют API. Их нельзя честно подтвердить или воспроизвести как отправку в этой версии. PDF создаётся на устройстве, а не на сервере. Отправка копии на почту не реализована по условию задания.

Текст/URL политики и страницы кейсов, направлений, команды, реквизитов не предоставлены. Политика открывает уведомление о недостающем документе, не сбрасывая форму. Названия отсутствующих страниц в шапке/подвале сохранены как текст, без выдуманных адресов. Прямые контакты из макетов открывают соответствующие приложения.

На ширинах без макета сетка адаптируется в CSS: ниже 850 px одна колонка, на узких телефонах кнопки и переключатели переносятся. Новых вопросов и возможностей не добавлено.
